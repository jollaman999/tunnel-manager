# 보안 후보 9건과 서비스 포트 바인드 주소

작성: 2026-09-23 · 대상: tunnel-manager · 갈래: architectural

## 이 문서가 있는 이유

"보안 사항 더 고칠 것 없어?" 로 시작한 survey 다. 대상이 지목되지 않았으므로 후보를 두 축으로
모아 표로 내고, 사용자가 고른 것을 여기 적는다. **고르지 않은 후보도 번호째로 남긴다** -
안 적으면 다음 세션에 같은 후보를 처음부터 다시 뽑는다.

후보를 모은 축은 둘이다. 한쪽만 돌리면 그 축의 후보만 나오는데 표에는 그게 전부인 것처럼 보인다.

|----|------|---------|
| 노출면·기능 | 인벤토리 (라우트별 인증·CSRF·비밀번호 재확인, 세션, 시크릿, TLS, 권한) | 후보 1·5·7 |

## 하는 것

### A. 서비스 포트의 바인드 주소

`manager.go:366` 이 모든 원격 포워드를 `0.0.0.0` 으로 요청하고, 바꿀 수단이 없다.
Host 의 `sshd` 가 `GatewayPorts yes` 면 그 포트가 호스트의 모든 인터페이스에 열린다.
코드는 `GatewayPorts` 가 이것을 좌우한다는 것을 알고 있고(`models.go:101-111`) 도달 범위를
측정까지 하는데, 요청할 주소를 고를 자리가 없다.

| | 결정 |
|---|---|
| 모델 | `HostServicePort` 에 `BindAddress string` (**두 번 고쳐 잡음, 아래 참조**) |
| 마이그레이션 | `AutoMigrate` 가 컬럼만 추가. 기존 행은 빈 문자열 |
| 빈 문자열의 뜻 | `0.0.0.0`. 데이터 마이그레이션이 없고, 지금 도는 터널의 도달 범위가 안 바뀐다 |
| 화면 | Host 등록·수정 폼에 `0.0.0.0` / `127.0.0.1` / `::1` / 직접 입력 |
| 안내문 | `0.0.0.0` 을 고른 동안만. 특권 포트 경고와 같은 `advise` 훅 |

### 어디에 두는지를 두 번째로 고쳐 잡음 (2026-09-23, v3.8.3 릴리즈 뒤)

**`Host` 로 옮긴 것도 틀렸다. 자리는 `HostServicePort` 다 - 할당 행이다.**

Host 하나가 여러 서비스 포트를 담당한다. 그중 하나는 바깥에 열어야 하고 다른 하나는 그 기계
안에서만 쓰여야 할 수 있다. Host 에 통으로 두면 그 둘이 같은 답을 강요받는다. 반대로 서비스 포트에
두면 Host 마다 다를 수 없다. **둘 다 다를 수 있어야 하고, 그것은 곧 짝마다 값이 있다는 뜻이다.**

포워드 하나가 정확히 그 짝이다 - `Tunnel` 의 기본키가 `(host_id, sp_id)` 이고, `HostServicePort` 가
같은 짝을 기본키로 갖는다. 값이 있어야 할 자리는 처음부터 거기였다.

| | 결정 |
|---|---|
| 필드 | `HostServicePort.BindAddress` |
| 마이그레이션 | `AutoMigrate` 가 컬럼을 더하고, **v3.8.3 이 `hosts.bind_address` 에 넣은 값을 그 Host 의 모든 할당에 복사한다.** 이것을 빼먹으면 v3.8.3 에서 루프백으로 묶어 둔 사람이 조용히 와일드카드로 돌아간다 |
| 빈 문자열의 뜻 | `0.0.0.0`. 그대로다 |
| 읽는 곳 | `tunnelAddresses` 가 할당의 값을 받는다. `reconcile.go:143` 이 이미 할당 행을 전부 읽고 있어 붙일 자리가 있다 |
| 재연결 | `connectionFingerprint` 가 local 주소를 이미 포함한다. 주소를 바꾸면 그 터널만 다시 만들어진다 |

화면 셋이다.

| 어디 | 무엇 |
|------|------|
| Host 추가 폼 | "서비스 포트 전부 할당" 을 켜면, **그 Host 에 만들어질 할당 전부에 쓸** 바인드 주소를 고른다 |
| 서비스 포트 추가 폼 | "모든 Host 에 할당" 을 켜면, **그 일괄에 쓸** 바인드 주소를 고른다. 여기만 선택지가 둘이다 - `0.0.0.0` 과 `127.0.0.1`. 특정 주소는 기계마다 다른 것이라 한 번에 여러 Host 에 걸 수 없고, 직접 입력 칸은 그것을 걸 수 있는 것처럼 보이는 칸이다 |
| Host 행의 "서비스 포트" 패널 | 체크한 것들에 **일괄 적용**할 주소를 고르고, **행마다 개별 수정**도 된다 |

### 어디에 두는지를 고쳐 잡음 (2026-09-23, 구현 뒤)

**처음에 이 필드를 `ServicePort` 에 두었고, 그렇게 구현해 `0b41c9b` 로 커밋했다. 틀렸다.**

어느 인터페이스에 여느냐는 **그 Host 의 성질**이다. 포워드 하나는 Host 와 서비스 포트의 짝이고
(`Tunnel` 의 기본키가 그 둘이다), 포트를 실제로 여는 것은 Host 의 sshd 다. 서비스 포트가 말하는
것은 어느 서비스를 어느 로컬 포트로 내보내느냐이고, 그 포트를 저쪽 기계의 어느 주소에 여느냐는
저쪽 기계에 대한 사실이다.

서비스 포트에 두면 그것이 강제로 하나가 된다. 서비스 포트 하나를 Host 셋에 할당했을 때 Host 마다
답이 다를 수 있는데 - 한 대는 인터페이스가 하나뿐이고 다른 한 대는 외부에 노출된 인터페이스를
가지고 있을 수 있다 - 그중 하나를 고르라고 강요하게 된다.

그래서 `Host` 로 옮긴다. 위 표의 "모델" 과 "화면" 줄만 달라지고, 나머지 결정(빈 문자열의 뜻,
선택지 넷, 안내문이 뜨는 조건, Host 에 물어보지 않는다)은 전부 그대로다.

**목록을 Host 에 물어보지 않는다.** 이 프로그램은 원격 명령을 실행할 수단이 없다 -
`internal/tunnel/` 전체에서 `NewSession`·`Run`·`Output` 이 0건이고, 하는 일은 포트 포워딩뿐이다.
쓸모 있는 답이 사실상 셋인 칸을 위해 원격 명령 실행이라는 표면을 새로 여는 것은 비용이 크다.
계정에 셸이 있어야 하고, OS 별 출력 파싱과 새 실패 경로가 붙는다.

**2번의 상한을 32MiB 로 낮추지 않는 이유.** `scryptLogN = 15` 는 이 프로그램이 **쓸 때** 쓰는
값이고 측정 근거가 붙어 있다 (`password.go:24-32`: 32MiB, 봉인 62ms·해제 62ms, i7-9700K,
`go test -bench`, 2026-09-19). `maxScryptMemory` 는 **읽을 때**의 상한이고 쓰기값의 16배로
일부러 잡아 둔 것이다 - 나중에 N 을 올려 쓴 파일도 지금 버전이 열 수 있게 하려는 것이다.
32MiB 로 낮추면 그 여유가 사라진다. 4배(128MiB)를 남기고, 곱셈을 막는 것은 동시성 제한이 한다.

### C. 토스트 알림

설정 저장·Host 등록·서비스 포트 등록의 성공 알림이 `#app` 맨 위 한 줄로만 그려져서
(`app.js` `paint`), 아래로 스크롤해 있으면 무슨 일이 있었는지 알 수 없다.

성공 알림을 화면 상단에 뜨는 토스트로 옮기고 3초 뒤 사라지게 한다. `role="status"`,
`aria-live="polite"`, `prefers-reduced-motion` 이면 페이드 없음.

**실패는 지금의 한 줄을 그대로 둔다.** 실패는 읽고 조치해야 하므로 저절로 사라지면 안 된다.

## 이미 제대로 돼 있어서 손대지 않는 것

조사 중 확인한 것이다. 다음에 같은 자리를 다시 파지 않기 위해 적는다.

| 영역 | 확인한 것 |
|------|-----------|
| XSS | `innerHTML`·`outerHTML`·`insertAdjacentHTML`·`document.write`·`eval` 전수 0건. 텍스트 30곳 전부 `textContent`. CSP `default-src 'none'` + 인라인 스크립트 해시 |
| CSRF | 비안전 메서드마다 `subtle.ConstantTimeCompare`, 쿠키가 아니라 세션이 보유한 토큰과 비교 (`auth.go:726`) |
| 인가 | `/api` 그룹 전체가 첫 라우트 등록 전에 `RequireSession` 을 단다 (`main.go:1645`). 미등록 경로도 포함 |
| 암호화 | AES-256-GCM, seal 마다 새 nonce (`crypto.go:68`), 헤더를 AAD 로 인증 (`password.go:305`), 키 파일 0600 + `O_EXCL`, `ErrWrongKey`/`ErrNotEncrypted` 분리로 재암호화 방지 |
| SSH 호스트 키 | TOFU 경로 없음. 제시된 키가 자동 승격되는 길이 없고 (`manager.go:495`), 교체는 계정 비밀번호가 필요하며 트랜잭션 안에서 행을 다시 읽는다 |
| 명령 주입 | 셸 호출 0건. `exec` 는 인자 배열뿐 |
| 경로·SQL 주입 | 설정 경로는 절대·볼륨·`..` 거부 (`settings.go:243`), 정적 자산은 `embed.FS` 에 `path.Clean` 루팅 (`web.go:152`), `Raw`/`Exec` 0건 |
| root 설치의 TOCTOU | 스테이징이 `os.MkdirTemp` (`main.go:1088`) - 0700, root 소유, 무작위 이름. 체크섬(`fetch.go:201`)과 복사 사이에 지역 사용자가 낄 창이 없다 |
